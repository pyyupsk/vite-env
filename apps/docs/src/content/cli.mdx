`@vite-env/cli` has three subcommands that work outside a Vite build.

```bash
npm install -D @vite-env/cli
```

Each subcommand loads `env.ts` from the current directory with `jiti`, which runs TypeScript without a build step.

## check

Validates the current environment against your schema. If validation fails, it exits with a non-zero code. Run it in CI before you deploy.

```bash
vite-env check
vite-env check --config ./env.ts --mode production
```

| Flag       | Default       | Description                                              |
| ---------- | ------------- | -------------------------------------------------------- |
| `--config` | `env.ts`      | Path to env definition file                              |
| `--mode`   | `development` | Vite mode (affects which `.env.[mode]` files are loaded) |

Output on success:

```
✔ 5 environment variables valid
```

Output on failure:

```
✖ Environment validation failed:
  DATABASE_URL: Invalid url
  SECRET_KEY: String must contain at least 32 character(s)
```

## generate

Writes a `.env.example` file from your schema. It lists every key with its type and default value, so a new developer knows what to fill in.

```bash
vite-env generate
vite-env generate --config ./env.ts --output .env.example
```

| Flag       | Default        | Description                 |
| ---------- | -------------- | --------------------------- |
| `--config` | `env.ts`       | Path to env definition file |
| `--output` | `.env.example` | Output path                 |

Example output:

```bash
# Auto-generated by @vite-env/cli — do not edit manually
# Run: npx vite-env generate

# ── Client variables (VITE_ prefix — available everywhere)
# VITE_API_URL: string — required
VITE_API_URL=

# ── Server-only variables (never sent to browser)
# DATABASE_URL: string — required
DATABASE_URL=
# PORT: number
PORT=3000
```

If you set `clientPrefix`, the section header shows your prefixes instead of `VITE_`.

## types

Writes `vite-env.d.ts` from your schema without a Vite build. Run it after you change the schema to update the types in your editor.

```bash
vite-env types
vite-env types --config ./env.ts
```

| Flag       | Default  | Description                 |
| ---------- | -------- | --------------------------- |
| `--config` | `env.ts` | Path to env definition file |

The file goes to the current directory. The plugin also writes it on every `buildStart`, so you need this command only when Vite is not running.

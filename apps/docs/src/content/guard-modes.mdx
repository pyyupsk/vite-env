title: Guard modes
description: What happens when a disallowed environment imports virtual:env/server.

---

A guard mode sets what the plugin does when an environment that is not in `allowedServerEnvironments` imports `virtual:env/server`. Set it with `onClientAccessOfServerModule`:

```ts
ViteEnv({
  onClientAccessOfServerModule: "error", // default since 0.8.0
});
```

An environment with `environment.config.consumer === 'server'` (Vite 8 and later) can always import `virtual:env/server`. Guard modes and leak detection skip it.

## warn

The plugin still serves the server module, but it prints a warning and writes `vite-env-warnings.log` to the project root. The build finishes but exits with code 1. Use this mode to find violations in CI while you clean up an existing codebase. It was the default before 0.8.0.

```
⚠ [vite-env] virtual:env/server imported from 'client' environment
  importer: src/components/UserCard.tsx
```

## error

The default since 0.8.0. If a disallowed environment imports the server module, the build fails at once and writes no output files.

## stub

The plugin replaces the server module with a stub that throws at runtime:

```ts
// What the 'client' environment receives when mode is 'stub'
throw new Error(
  '[vite-env] virtual:env/server was imported in the "client" environment. ' +
    "This module is server-only and was replaced with a stub. " +
    "To allow this environment: add it to allowedServerEnvironments. " +
    'To suppress this stub: ensure this import never executes in the "client" environment.',
);
```

Use `stub` for test environments (Vitest with jsdom) or for shared files that import the server module but never run that code in the browser.

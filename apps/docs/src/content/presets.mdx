A preset adds the variables that a hosting platform sets to your schema. Import it from `@vite-env/core/presets` and pass it in the `presets` array.

Each preset has a `detect` function that looks for the platform's marker variable (`VERCEL=1`, `RAILWAY_ENVIRONMENT_ID`, `NETLIFY=true`). On the platform, the plugin validates preset variables strictly. Everywhere else, they are optional, so local `vite dev` works without fake platform values. Keys that you redefine in your own `server` or `client` block are always strict.

For the same reason, `vite-env.d.ts` types preset variables as optional. In code that runs only on the platform, narrow them or assert them.

The plugin caches `detect` results for each process, up to 32 entries per function. Repeated validation calls from plugins or build steps do not run `detect` again.

## Vercel

```ts
import { defineEnv } from "@vite-env/core";
import { vercel } from "@vite-env/core/presets";
import { z } from "zod";

export default defineEnv({
  presets: [vercel],
  server: {
    DATABASE_URL: z.string().url(),
  },
});
```

Adds (server-only):

| Variable                        | Type                                         |
| ------------------------------- | -------------------------------------------- |
| `VERCEL`                        | `'1'`                                        |
| `VERCEL_ENV`                    | `'production' \| 'preview' \| 'development'` |
| `VERCEL_URL`                    | `string` (bare hostname, no scheme)          |
| `VERCEL_PROJECT_PRODUCTION_URL` | `string`                                     |
| `VERCEL_DEPLOYMENT_ID`          | `string`                                     |
| `VERCEL_REGION`                 | `string` (optional)                          |
| `VERCEL_GIT_COMMIT_SHA`         | `string` (optional)                          |
| `VERCEL_BRANCH_URL`             | `string` (optional)                          |

The preset also adds more git fields and skew protection fields.

## Railway

```ts
import { railway } from "@vite-env/core/presets";

export default defineEnv({
  presets: [railway],
  server: { DATABASE_URL: z.string().url() },
});
```

Adds (server-only): `RAILWAY_ENVIRONMENT_ID`, `RAILWAY_ENVIRONMENT_NAME`, `RAILWAY_SERVICE_ID`, `RAILWAY_SERVICE_NAME`, `RAILWAY_PROJECT_ID`, `RAILWAY_PROJECT_NAME`, `RAILWAY_DEPLOYMENT_ID`, and optional git and domain fields.

The preset leaves out `PORT`, because many tools set a variable with that name. If you need it, define it yourself.

## Netlify

```ts
import { netlify } from "@vite-env/core/presets";

export default defineEnv({
  presets: [netlify],
  server: { DATABASE_URL: z.string().url() },
});
```

Adds (server-only):

| Variable     | Type                                                           |
| ------------ | -------------------------------------------------------------- |
| `NETLIFY`    | `'true'`                                                       |
| `BUILD_ID`   | `string`                                                       |
| `CONTEXT`    | `'production' \| 'deploy-preview' \| 'branch-deploy' \| 'dev'` |
| `DEPLOY_ID`  | `string`                                                       |
| `DEPLOY_URL` | `string` (full URL)                                            |
| `URL`        | `string` (full URL)                                            |
| `BRANCH`     | `string`                                                       |
| `COMMIT_REF` | `string`                                                       |

---

Presets are plain `{ server, client }` objects. For more control, spread them into your own blocks. If a key name collides, your key wins.

## How it works

During `generateBundle`, vite-env scans every client-bound output chunk for server-only variable values. It parses each chunk as JavaScript using an AST parser (`oxc-parser`), extracts all evaluable string values (literals, template literals, string concatenation), and checks whether any match a server secret. If a match is found, the build throws immediately:

```
[vite-env] Server environment variables detected in client bundle!

  ✗ DATABASE_URL found in dist/assets/index-Bg3kL9xM.js

  These variables are marked as server-only and must never reach the browser.
```

This catches leaks that guard mode misses — for example, a value passed through a prop chain or inlined by the bundler's constant folding.

The detection includes:
- Literal strings in quotes (`"my-secret"`, `'my-secret'`, `` `my-secret` ``)
- String concatenation (`"prefix" + env.SECRET`)
- Template literals with expressions (`` `key=${SECRET}` ``)
- Base64 and hex encoded representations of server values

Leak detection runs **only on client builds** — skipped when `build.ssr` is true, the current environment is listed in `serverEnvironments`, or the environment's `consumer` is `'server'` (Vite 8+ environments with `environment.config.consumer === 'server'`).

## False positives

Values shorter than 8 characters are skipped. Short strings appear frequently enough across unrelated code that matching on them would produce too many false alarms. When values are skipped a warning is logged:

```
⚠ [vite-env] Leak detection skipped 2 server variable(s) with values
  shorter than 8 chars: PORT, NODE_ENV
```

If you hit a false positive on a longer value, verify whether the value is genuinely reaching the client. If it is intentional, move that variable to the `client` block in your schema.

## Disabling

No configuration option — leak detection is always enabled on client builds. This is intentional: it is a safety net, not a feature to toggle off.

## Vendor chunks

Pure vendor chunks — where all modules come from `node_modules` — are skipped automatically. Only chunks containing user code are scanned. Mixed chunks (user + vendor modules) are scanned fully.

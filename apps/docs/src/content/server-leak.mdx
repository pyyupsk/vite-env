## How it works

During `generateBundle`, vite-env scans every output chunk that goes to the client for the values of server-only variables. It parses each chunk with `oxc-parser` and collects every string it can work out: literals, template literals, and concatenated strings. If one of them matches a server value, the build throws:

```
[vite-env] Server environment variables detected in client bundle!

  ✗ DATABASE_URL found in dist/assets/index-Bg3kL9xM.js

  These variables are marked as server-only and must never reach the browser.
```

This finds leaks that guard modes cannot see, for example a value passed down through props, or a value the bundler inlined as a constant.

The scan finds:

- Literal strings in quotes (`"my-secret"`, `'my-secret'`, `` `my-secret` ``)
- String concatenation (`"prefix" + env.SECRET`)
- Template literals with expressions (`` `key=${SECRET}` ``)
- Base64 and hex encoded representations of server values

Leak detection runs only on client builds. It does not run when `build.ssr` is true, when the environment is in `allowedServerEnvironments`, or when `environment.config.consumer` is `'server'` (Vite 8 and later).

## False positives

The scan skips values shorter than 8 characters, because short strings occur everywhere and would match by accident. The plugin logs a warning for each skipped value:

```
⚠ [vite-env] Leak detection skipped 2 server variable(s) with values
  shorter than 8 chars: PORT, NODE_ENV
```

If a longer value matches and you think it is a false positive, find out whether the value really reaches the client. If the client needs it, move that variable to the `client` block of your schema.

## Disabling

You cannot turn leak detection off. It always runs on client builds, by design.

## Vendor chunks

The scan skips chunks where every module comes from `node_modules`. It scans every chunk that holds your code, including chunks that mix your code with vendor code.

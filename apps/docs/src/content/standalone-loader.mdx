`virtual:env/server` and `virtual:env/client` only resolve inside Vite's module graph. Running a plain script with `bun scripts/seed.ts` or `node scripts/migrate.js` bypasses Vite entirely, so those imports fail.

`@vite-env/core/load` runs the same validation outside of Vite and returns the same typed result.

## Usage

Pass your existing `env.ts` config. You do not write the schema twice:

```ts
// scripts/seed.ts
import { loadEnv } from "@vite-env/core/load";
import config from "../env";

const { server, client } = await loadEnv(config);

server.DATABASE_URL; // string — fully typed, same schema as virtual:env/server
client.VITE_API_URL; // string — only VITE_* vars
```

It reads the same `.env` files in the same priority order, and validates with Zod or Standard Schema like the Vite plugin.

## Return value

`loadEnv` returns `{ server, client, all }`:

| Property | Contains                             |
| -------- | ------------------------------------ |
| `server` | All validated vars (server + client) |
| `client` | Only `VITE_*` vars                   |
| `all`    | Alias for `server`                   |

`server` matches `virtual:env/server`, and `client` matches `virtual:env/client`.

## Options

```ts
const env = await loadEnv(config, {
  mode: "production", // default: process.env.NODE_ENV ?? "development"
  envDir: "./", // default: process.cwd()
});
```

| Option   | Default                                 | Description                                                     |
| -------- | --------------------------------------- | --------------------------------------------------------------- |
| `mode`   | `process.env.NODE_ENV ?? "development"` | Controls which `.env.[mode]` and `.env.[mode].local` files load |
| `envDir` | `process.cwd()`                         | Directory to search for `.env` files                            |

## Error handling

If validation fails, `loadEnv` throws with one line per field:

```
Error: [vite-env] Validation failed:
  - DATABASE_URL: Invalid url
  - JWT_SECRET: String must contain at least 32 character(s)
```

Call `loadEnv` at the start of your script, so that a bad env stops the script before it does any work. The Vite plugin does the same on `buildStart`.

## Standard Schema

`defineStandardEnv()` configs work the same way:

```ts
import { loadEnv } from "@vite-env/core/load";
import config from "../env"; // defined with defineStandardEnv()

const { server } = await loadEnv(config);
```

For Standard Schema configs, the return type is `Record<string, unknown>`. TypeScript cannot infer output types from Standard Schema validators in general.

## Requirements

Vite 8.0.0 or later is a peer dependency. `@vite-env/core/load` reads `.env` files with Vite's own `loadEnv`, so you must install Vite even for plain Node or Bun scripts.

## Merge priority

The same as the Vite plugin, highest first:

1. `process.env` (secrets from your CI pipeline win)
2. `.env.[mode].local`
3. `.env.[mode]`
4. `.env.local`
5. `.env`

## virtual:env/client

Holds only the `client` keys from your schema. Any module that runs in the browser can import it.

```ts
import { env } from "virtual:env/client";

// Only VITE_* keys present
console.log(env.VITE_API_URL);
```

## virtual:env/server

Holds every validated variable, both `server` and `client` keys.

```ts
import { env } from "virtual:env/server";

const db = createClient(env.DATABASE_URL);
const server = createServer({ port: env.PORT });
```

If a disallowed environment imports it, the configured [guard mode](/docs/guard-modes) applies.

## Emitted module shape

Both modules export a frozen object. In strict mode, a write to it throws:

```ts
// What virtual:env/server resolves to at runtime
export const env = Object.freeze({
  DATABASE_URL: "postgres://...",
  PORT: 3000,
  VITE_API_URL: "https://api.example.com",
});
export default env;
```

## Type generation

On every `buildStart`, the plugin writes `vite-env.d.ts` to the project root. This file declares both virtual modules with types inferred from your Zod schema:

```ts
// vite-env.d.ts (auto-generated — do not edit)
declare module "virtual:env/client" {
  const env: {
    readonly VITE_API_URL: string;
  };
  export { env };
  export default env;
}

declare module "virtual:env/server" {
  const env: {
    readonly DATABASE_URL: string;
    readonly PORT: number;
    readonly VITE_API_URL: string;
  };
  export { env };
  export default env;
}
```

For editor autocomplete, add `vite-env.d.ts` to the `include` array in `tsconfig.json`, or reference it with a triple-slash directive.

## SSR

In SSR mode, both modules resolve on the server. `virtual:env/client` still holds only the client keys, the same as the browser gets.

```ts
// vite.config.ts
export default defineConfig({
  plugins: [ViteEnv({ configFile: "./env.ts" })],
  // No extra SSR config needed — 'ssr' is in allowedServerEnvironments by default
});
```

If the plugin does not detect your edge runtime, add it to `allowedServerEnvironments`:

```ts
ViteEnv({ configFile: "./env.ts", allowedServerEnvironments: ["ssr", "workerd"] });
```

If you set `clientPrefix` in your schema, `virtual:env/client` holds only the keys with that prefix. The rule stays the same. Only the prefix changes.
